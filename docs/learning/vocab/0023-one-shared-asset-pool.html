Vocab: One Shared Asset Pool

pool separation
Two consumers drawing "the same kind" of content from unrelated sources (rigged models vs composite parts). The root cause behind both "they don't match" and "additions don't propagate".
dispatch hook
An existing per-entity branch between implementations (customLooks.find(i) ? composite : rigged). Unification widens the hook until one branch is unreachable — no new machinery.
authored-or-derived resolver
The one rule mapping an entity to pool content: hand-authored value when valid, else a value derived deterministically from identity (randomizeLook(hash(name))). Serves an art-directed cast and procedural spawns with the same function.
deterministic fallback
A derived default computed from stable identity rather than fresh randomness — the same input yields the same result every run, so no state needs persisting and nothing reshuffles on launch.
demote, don't kill
Stale references degrade to the fallback with a logged reason instead of failing the whole record — an NPC with a removed hair part still spawns, loudly.
structural vs catalog validation
The parser enforces shape (five items); existence against the live catalog is checked where the catalog lives, at spawn. Keeps the file format decoupled from the pool's contents.
priced trade-off
A loss taken knowingly: fidelity (rigged animation) exchanged for cohesion, with the decision, its reason, and the off-ramp written down — distinguishable from an accidental regression.
data-level acceptance test
Asserting the product promise on the data (authored, valid, pairwise-distinct looks) instead of its rendered consequence — cheap, exhaustive, and survives art changes.
