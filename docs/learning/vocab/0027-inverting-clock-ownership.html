Vocab 0027 — Clock Ownership and Match Pacing

Terms from lesson 0028 (inverting a clock's ownership), issue #155.

clock ownership
Which subsystem is authorised to WRITE the shared world hour on a given frame. In this codebase it is free roam (WorldState::advanceTime) or a match (MatchClock::worldHour), never both. Distinct from who reads the hour, which is everybody.
driven clock
A clock whose value is DERIVED from another system's progress rather than accumulated from elapsed time. worldHour() is a pure function of phaseProgress(), so the sky is always exactly as far through the day as the investigation phase is. Contrast a ticked clock, which accumulates dt.
value coupling
Consumers depend on reading a shared variable, not on being called by, or calling, its producer. It is what let #155 swap the clock's writer without touching any of the six systems that read the hour. Contrast call coupling and event coupling, both of which bind consumers to a specific producer.
single write site
A design where a rule that cannot be expressed in the type system ("exactly one owner") is expressed in the code's topology instead: collapse the mutually exclusive branches into one function so there is no second place to get it wrong. Here, advanceWorldClock.
state-as-representation
Storing a fact ONCE, in a form that cannot disagree with itself — here std::optional<MatchClock>, whose engaged-ness IS the answer to "is a match running". Contrast a bool flag beside the object, which is a second representation of the same fact and can therefore drift from it.
phase machine
MatchClock's cycle: Intro → Investigation → Vote → Resolution, looping back to Investigation until the day limit, then Ended. Advances at most ONE transition per advance() call, carrying overshoot forward so a long frame delays a boundary rather than losing its event.
Intro phase
The opening beat of a match, before the first Investigation. Sized to the cutscene budget but NOT gated by it — with no cutscene playing it simply elapses, which is what kept MatchClock mergeable while the cutscene system was still unbuilt. Holds the clock at dayStartHour, unlike every other holding phase.
diegetic countdown
A deadline the player reads from the world itself rather than from a HUD element. dayEndHour (20.0) sits strictly inside DayNight's dusk band (18.0–21.0), so the sky going orange IS the vote timer. A test pins the overlap, because the coupling is load-bearing and invisible.
phase overshoot carry
When advance(dt) crosses a phase boundary, the leftover time is carried into the next phase instead of discarded. A frame longer than a whole phase (debugger, alt-tab, stalled load) therefore delays the following boundary rather than skipping its event — and the vote hangs off exactly those events.
byte-identical regression check
Proving an untouched code path really is untouched by producing the same artefact before and after a change and comparing hashes — here a deterministic --frames capture at a fixed camera, compared by md5. Converts "looks the same" into a comparison that either holds or does not.
