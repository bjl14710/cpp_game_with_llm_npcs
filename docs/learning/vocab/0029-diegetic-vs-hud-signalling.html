Vocab 0029 — Diegetic Versus HUD Signalling for Time Pressure

Terms from lesson 0030 / issue #157.

diegetic signal
Information carried by something inside the fiction — the dusk light, a closing shop, a siren. Free to read because the player is already looking at the world. Imprecise by nature, which is a feature when the design wants pressure rather than a number.
HUD signal
Information drawn on the glass in front of the world. Exact and unambiguous, and it costs a glance away from the game. The default reflex, because it is cheap to add.
shared-variable signalling
Getting a second signal for free because two systems already read the same value. dayEndHour inside DayNight's dusk band makes the sky a rendering of the phase clock rather than a metaphor for it — the expensive part (sweep, light model, fog) already existed.
stated HUD budget
A written limit on how much a HUD may grow, with the consequence of exceeding it. "Past two lines and the diegetic design has been abandoned" converts each future addition from a fresh judgement into a decision already on record. HUDs grow by accretion; each step is individually reasonable.
integer glyph advance
raylib's built-in bitmap font computes spacing by integer division, so sizes 14 through 18 render identically. Any type hierarchy inside that range does not exist at runtime. The reason this codebase keeps a 10/20/30/44 ladder.
single read site
A value read in exactly one place, so a rule about when it applies becomes a property of the topology. pendingRules is read only where a match is constructed, which is why a mid-match settings edit cannot reach a running clock.
weak vs strong invariant
Weak: "do not do X", enforced by every future author reading a comment. Strong: "there is no way to do X", enforced by structure. When the strong form costs the same, it is always the better trade.
trailing default
A final else or default: that serves both "the last real case" and "a case nobody wrote". It makes a missing case indistinguishable from a handled one — Sandbox and Model were titled "Multiplayer" for months this way.
exhaustive switch (no default)
A switch over an enum with no default: label, so adding an enumerator is a compiler warning. Used here by the page title, phaseName() and arrestLineFor().
derived layout
Computing spacing and size from the item count against the available band rather than from fixed offsets. Makes overflow impossible instead of invisible: the old fixed form put the tenth menu row's bottom edge at y=734 in a 720px window.
latent constant disagreement
A hardcoded constant that must agree with a count nobody re-checks. The agreement holds until someone adds an item, and the arithmetic gives no hint. Derive one from the other and it is maintained by construction.
harness boundary
The precise line past which the test suite cannot verify anything. Here tests/Makefile globs src/core/*.cpp and nothing else, so all of src/app/ is verified by screenshot or not at all. Knowing where the line is tells you which changes demand a capture.
deferred-frame handoff
Acting one frame after a transition so same-frame consumers still see the state that produced it. Safe only when the terminal state is genuinely terminal — pinned here by a test asserting a day-limit end fires nothing afterwards.
