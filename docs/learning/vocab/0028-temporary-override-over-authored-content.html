Vocab 0028 — Layering a Temporary Override Over Authored Content

Terms from lesson 0029 / issue #156.

authored content
Data written by a human into a content file and read by the game — personas/*.persona, traits/*.trait, banks/*.bank, cutscenes/*.cutscene. Treated as read-only at runtime. The moment code mutates it, restoring it becomes the code's problem and a diff stops being reviewable.
destination override
A nullable field holding a temporary target that outranks the authored one at the single point the authored one is read. Here Npc::gatherTarget_, an optional<Vec3> consulted before the schedule lookup. Its defining property is that nothing is overwritten, so undo is reset().
out-ranked, not suspended
The relationship between the override and the authored value: the schedule still resolves, still reports its activity label, and still resumes the instant the override clears. Contrast suspended, where the authored system stops evaluating — which requires remembering how to restart it.
restore-by-reset
Undo implemented as clearing an override rather than replaying a saved previous state. Cheap and total: it cannot half-fail, and it needs no bookkeeping. The diagnostic question is "does my restore need to know what was there before?" — if yes, the design overwrote something.
guard bundling
Combining unrelated early-return conditions into one if. The pre-#156 walk bundled "something else owns this NPC" with "there is no authored answer right now". They demand different treatment, and separating them is a behaviour change until proven otherwise — see incidental behaviour change.
incidental behaviour change
A change in observable behaviour that falls out of a refactor rather than being intended by it. Restructuring the walk would have started clearing activity_ for clockless NPCs, which used to keep their last label. Caught by re-wrapping the assignment; the class of bug surfaces months later, far from the commit that caused it.
presentation-only system
A system that changes what is seen and is never consulted by a mechanic. The gather is one: a resident who cannot reach the plaza votes from where they stand. The test is whether the feature failing entirely can break anything other than the view.
entry-keyed transition handling
Reacting to the state being entered rather than the one being left. to == Investigation || matchEnded covers every route back to normal life, including ones not yet written, whereas from == Vote covers only the routes you thought of. Relies on the handler being idempotent.
authored marker
A hand-placed reference point used in preference to a computed one, because the computed one is wrong on the actual map. plazaGatherSpot is the marker here — written as a function derived from the zone bounds so it cannot silently drift from the map it describes.
geometric centre vs. clear space
A centre is a statement about bounds, not about emptiness. zoneCentre("plaza") returns (0, 0), which is inside Gus's cart (x ∈ [-3, 3], z ∈ [-2, 2]). Spatial defaults need checking against what is authored at the coordinate, not just against the region's extent.
spacing vs. formation logic
Spacing distributes agents so they do not occupy one point; formation logic assigns ordering, facing, and re-packs when membership changes. The plaza ring is spacing: a resident who dies keeps their slot, and the resulting gap is the "who is missing?" signal the scene exists for.
vacuous test
A test that passes for a reason unrelated to what it claims. The first fixture placed residents inside the bakery's collider, so the "moves exactly as before" regression compared "did not move" with "did not move". A movement test that never moves always passes — assert the travel before asserting anything about it.
