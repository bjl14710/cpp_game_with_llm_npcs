Drill 0031 — One Implementation Across a Language Boundary

Answer before expanding. Source: lesson 0031, issue #304.

1. A Python harness needs a prompt that C++ assembles. Give the two options and say which this codebase takes.
Answer Re-implement the assembly in Python, or add a mode to an existing C++ tool that prints it and shell out. The codebase takes the second — persona_prompt --state — and had already taken it once before for reply parsing with --parse.
2. "Duplication is a maintenance cost" understates the problem here. Why?
Answer The probe exists to measure the consequences of the role block's PLACEMENT. A Python copy would have its own placement, so the measurement would be of the copy rather than of the game — and would look exactly like a real result. That is not a bug you eventually notice; it is an invalid instrument producing plausible answers indefinitely.
3. The comment above --parse names a sibling tool that took the shortcut. Which, and why does citing it strengthen the argument?
Answer tools/bench_npc_models.py, which duplicates the mood keyword list in Python and whose own comment admits it has to be hand-synced. The codebase contains both the pattern and the counterexample, with the counterexample conceding fault — the failed variant is usually more instructive than the successful one.
4. What is the actual payload of stateMode(), and what is everything else in the function?
Answer One line: the call to the same renderSystemPrompt overload, with the same argument order, that Npc::ask uses. Everything else is argument preparation — loading the persona, resolving traits, finding the role, rendering the role block.
5. The game demotes an unknown trait id with a log; the tool refuses. Both are correct. Explain.
Answer They answer to different worst outcomes. For the game it is "a player loses a character over a typo", so it degrades and continues. For a measurement it is "a number that means nothing", so it refuses. A measurement taken with a silently missing trait is worse than no measurement, because it still produces a number and that number enters a comparison.
6. Why does every failure path print zero bytes rather than a partial prompt?
Answer A partial prompt reads as a result rather than as a broken fixture. The one outcome a probe must never be handed is something that looks like data but is not.
7. Which single check carries most of the weight, and what does it protect?
Answer An uncast persona must render BYTE-IDENTICALLY through --state and through the plain mode. Probes work by comparing a prompt with a role block against one without; if the two paths differ by even a newline, that comparison measures the tool instead of the role — and still yields a number.
8. Why is findRole's result bound through a named vector rather than called inline?
Answer It returns a pointer INTO its argument. findRole(loadAllRoles(dir), id) dangles the moment the statement ends — Role.hpp:104 records that this is how a test failed the first time it ran, passing the null check and then reading freed memory.
9. Why is the contract checked by a shell script rather than doctest, and what is the reusable reasoning?
Answer tests/Makefile globs src/core/*.cpp and nothing else, so tools/ is outside the test binary. The reasoning: rather than treating "untestable in the harness" as untestable, identify what the harness DOES cover (the core contract is pinned at test_role.cpp:294) and write a check for the residue — whether the tool passes the right arguments to already-tested code.
10. State the four-part general shape.
Answer Export the behaviour rather than re-deriving it; weigh duplication by what the copy is used for; fail closed at a measurement boundary even where the product fails open; pin the seam with an identity check against the path that already worked.
