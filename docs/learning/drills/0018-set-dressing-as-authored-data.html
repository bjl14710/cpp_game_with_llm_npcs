Drill: Set Dressing as Authored Data

1. Adding a mailbox

You want a mailbox outside the bakery. List the three data edits — and the zero code edits — required.

Answer

(1) A Building row in City::makeDowntown (id + AABB + height), (2) a curated_ entry mapping the id to a model stem, (3) a sizeSpecs_ Uniform height. The renderer's buildings pass and collision pick it up automatically; add the id to the completeness test's table.

2. Why does the police car park beside the station, not in front of it?

Answer

The station fronts an X-running street, but KayKit cars are Z-long at identity and drawModelUniform applies no rotation — a car there would sit perpendicular to the road. Parking on the Z-running street flanking the station block keeps the orientation correct with pure data (the zero-new-rendering-code constraint).

3. The invisible cage

The first draft gave each car a 6.5-unit-long AABB centered in the lane. Both failure modes?

Answer

Visually the car floats mid-lane (the Uniform draw centers the small model in the big box), and physically the player bounces off empty air around it — an invisible wall. Colliders must match the visual footprint: hug the curb, ~4 units long.

4. What does the clearance test actually check, and why probe circles instead of points?

Answer

For every persona home spot and the four zebra centers, circleIntersectsAny(x, z, 0.5) must be false. The 0.5 radius is a walking NPC's collision circle — a point probe could pass while the NPC's body still clips a collider, silently trapping ReturnHome pathing.

5. When is a new system actually warranted?

Under what conditions would authored data rows stop being the right tool for set dressing?

Answer

When placement stops being hand-designed: procedural scatter (hundreds of props), runtime spawning/despawning, or physics-driven props. Until the count or dynamism outgrows a reviewable list, rows in the authored table stay simpler, testable, and diffable.
