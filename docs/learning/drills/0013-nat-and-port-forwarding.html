NAT and Port Forwarding

1. Your friend across town tries your 192.168.1.20:40605 and times out. Why was this doomed from the start?

Private ranges (10/8, 172.16/12, 192.168/16) exist precisely so every home can reuse them behind one public IP.

2. Why does outbound traffic (browsing) work from behind NAT while inbound hosting doesn't?

The router only knows where to deliver packets for flows it has already seen leave.

3. What does the port-forward rule "TCP 40605 → 192.168.1.20" actually tell the router?

It's precisely the missing table entry NAT can't infer on its own, scoped to one port and one host.

4. Why is Tailscale/ZeroTier usually the better recommendation for a 4-friend game night?

A forwarded port is open to the whole internet and needs router admin access; an overlay network is private by construction and installs like an app.

5. Written recall:

List the three-step "can't connect" debugging ladder from the lesson (same machine → LAN → internet) and what each step isolates.

Reference answer1) 127.0.0.1:port on the host's own machine — isolates "is the server even running/bound". 2) The host's 192.168.x.x from another machine on the same Wi-Fi — isolates OS firewall prompts and AP client isolation. 3) Across the internet — requires port forwarding or an overlay VPN; a bare public IP will hit the game's 4s connect timeout.
