Drill 0027 — Bind Pose vs Rest Pose in glTF Skinning

Answer before expanding. Source: lesson 0027, session-9 issues #139/#142.

1. Name the two default skeleton configurations a skinned glTF carries, where each is stored, and which one the mesh vertices are stored in.
Answer Bind pose — stored (inversely) in skins[0].inverseBindMatrices; the mesh vertices are stored in this pose. Rest pose — the joint nodes' local TRS values composed down the hierarchy; it's what you get with no animation playing.
2. Write the standard skinning equation for a vertex stored in bind space and explain the role of the IBM.
Answer 
v' = Σ w_j · G_j(pose) · IBM_j · v
The inverse bind matrix moves the vertex from bind space into joint-local space; the joint's global pose matrix then places it in the current pose. Without the IBM you are implicitly assuming vertices were stored in the rest pose.
3. The pack's characters froze in T-pose but their fingers and legs animated. Explain BOTH halves of that symptom in terms of rest-vs-bind agreement.
Answer raylib computes rest-relative deltas and assumes vertices are in rest space. For joints where rest == bind (legs, fingers), the assumption holds and animation looks right. For the arms, rest (down) ≠ bind (T-pose): clips keep joints near rest, deltas ≈ identity, and the T-pose vertices render unchanged.
4. Why was ten lines of python more decisive than another renderer experiment?
Answer glTF is JSON: composing node TRS down the hierarchy yourself gives ground truth about the DATA with no engine assumptions in the loop. Printing the wrist's global rest position ((±0.25, 1.01) — hip height) proved the file was arms-down and shifted all suspicion onto the engine's conventions.
5. State the fix in one formula and say when it runs.
Answer Re-bake every vertex from bind space to rest space ONCE at load: 
v_rest = Σ w_j · (restGlobal_j · IBM_j) · v_bind
then re-upload the vertex/normal buffers. Static draws now show the rest stance and rest-relative animation deltas become correct.
6. After the re-bake, a witch head mixed onto a soldier body follows the walk cycle with zero attachment code. Why?
Answer Both files share one skeleton and animation library. Posing each model with the same clip at the same clock produces identical neck-bone trajectories, so the head's skinned vertices move exactly as if parented to the body's neck — the "attachment" is the shared rig itself.
7. Transfer: a teammate imports a character that looks correct in Blender but stands twisted in your custom engine, and only some limbs animate. List your first three checks, in order.
Answer (1) Does the engine read inverseBindMatrices, or does it assume bind == rest? (2) Compute a limb's global rest position from the raw JSON — does the DATA say the pose differs from what the engine shows? (3) Compare a frozen limb's animated local TRS to its rest TRS: deltas near identity confirm the rest-relative mismatch rather than missing channels.
