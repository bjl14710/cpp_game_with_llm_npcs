Socket Contracts: Per-Part Attach Points vs Per-Pair Offsets

The character creator's core promise is "any combination of parts renders correctly". Whether that promise scales depends entirely on where the attachment knowledge lives.

The trap: per-pair offsets

The obvious first implementation is a table of hand-tuned offsets: "round eyes on the blocky head sit at (0, 0.42, 0.38); on the round head at (0, 0.40, 0.30)…" That table grows as parts × parts — adding one head means re-tuning an offset against every eye and hair part, and a missed pair ships as floating eyeballs.

The contract: each part describes only itself

PartDef {
  id:        "head_round"
  localSize: (0.72, 0.72, 0.72)      // anchor at bottom-center
  sockets:   { eyes: (0, .40, .30),   // MY eye position, MY local space
               hair: (0, .64, 0) }
}
CategorySpec rows:  Head→Body via "head",  Eyes→Head via "eyes",  Hair→Head via "hair"

Assembly is a fold over the category specs: each part lands at parent anchor + parent's declared socket. Knowledge is parts + categories, not parts²: a wider head declares its eye socket farther forward and every eye part inherits that placement for free. Adding a category (a hat, a held item) is one spec row plus socket entries on the parts that can carry it — no restructuring.

Where the size contract fits

The brief flagged the interaction. Resolution order is the whole answer: sockets resolve in unscaled local space first, the assembly's total height is measured, then one uniform scale takes the figure to the same 1.8-unit character height contract the pack models use. Scale per-part and sockets drift; scale once at the end and alignment is invariant. Swapping the art style later means re-authoring parts — the contract keeps world proportions fixed on top of everything else.

Guard rails that make it hold

  • Style tags (round/blocky/any) gate combinations in the validator, the picker, and the randomizer — one predicate (styleCompatible), three call sites.
  • Exhaustive test: every parts combination is assembled; validity must equal pairwise style compatibility, all categories must place, and the head must sit above the body's midpoint. The promise is checked at the data level, not eyeballed per pair.
  • Explicit "none": baldness is a real zero-size part, so the assembly never has holes and the picker never needs a special case.
The general shape. Whenever "any A works with any B" is the requirement, make A and B each describe themselves against a shared contract and derive the pairing — the moment knowledge about a specific (A,B) pair appears anywhere, the combinatorial promise is already broken.
