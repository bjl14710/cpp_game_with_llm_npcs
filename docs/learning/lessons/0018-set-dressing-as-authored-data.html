Lesson 0018 · World building · from issue #66 (street dressing)

Set Dressing as Authored Data

Making a game world feel lived-in usually tempts people toward new systems — spawners, prop managers, scatter tools. This change added five parked cars and three alley props with zero new code: every object is a data row in the same authored list that buildings use, and the existing render/collision pipeline does the rest.

The pipeline you already have is the feature

City::makeDowntown()      one Building row: id + AABB + height
        ↓
Assets curated_           id → model stem  ("police_car" → "car_police")
Assets sizeSpecs_         id → Uniform world height (1.5)
        ↓
drawCity buildings pass   model scaled/centered on the authored AABB
City collision            the SAME AABB blocks the player

Because visuals render from collision data, a prop can't be walk-through and a collider can't be invisible. Liveliness becomes a data authoring problem: pick spots, write rows.

Constraints make placement a real design task

  • Model orientation: KayKit cars are Z-long at identity and the Uniform path doesn't rotate — so every parking spot must sit on a Z-running street. The police car parks beside its station block, not on the station-front street. Cheaper than adding rotation support, and honest about what the pipeline can express.
  • Collision honesty: the first draft used generous 6.5- unit boxes centered mid-lane — the car floated in an invisible cage, visibly "parked" in the middle of the road. Boxes now hug the curb and match the visual footprint (~4 units).
  • Don't trap the actors: spots avoid zebra tiles, junctions, shop doors, and every persona's home position (Hal at (36,0) was the close call).

Lock the invariants with data-driven tests

Two cheap tests make the whole category regression-proof:

  • Completeness: every visible obstacle id resolves via findBuilding and collides at its probe point — a new prop that skips City fails immediately.
  • Clearance: every persona home spot and the four crossing centers keep a clear 0.5-radius circle — future set dressing that would trap an NPC fails before a screenshot is ever taken.
The pattern. When adding content, ask "which existing table does this belong to?" before "which new system do I write?" A world where props, cars, lights, and bushes are all rows in one authored list stays auditable — the tests literally iterate the design.
