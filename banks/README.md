# Line banks

Authored NPC replies for recurring conversation topics, served locally instead
of round-tripping to the model. Baseline to beat: 2.7 s to first token, 4.5 s
total (`bench/REPORT.md`). A bank hit targets under 50 ms.

Plan: `.claude/plans/npc-line-bank.md`. Loader: `src/core/LineBank.cpp`.

## These files are generated, and that is not a reason to skip reviewing them

`tools/refine_lines.py` regenerates them nightly and opens a **draft PR**. The
whole reason the format is plain text rather than a database or a blob is that a
night of generated content has to review as a normal diff. Nothing here reaches
players until a human merges that PR.

This preserves the contract `src/core/RatingLog.hpp` documents and a test pins:
thumbs-up replies never feed back into live prompts automatically. The nightly
job reads the ratings log as *input signal*; the human still approves.

## Format

One file per persona, `<stem>.bank`, same `key = value` shape as
`personas/*.persona` and `traits/*.trait`. Blank lines and `#` comments are
ignored. Leading whitespace on topic-scoped keys is cosmetic.

```
# banks/baker.bank — generated by tools/refine_lines.py, human-approved via PR.
persona = Marge Holloway

topic = greeting_first
  familiarity = first
  trigger = hello
  trigger = hi there
  trigger = good morning
  reply = Well, good morning! You've got the look of someone who hasn't had breakfast. [[MOOD: happy]]
  reply = Morning, love. Sourdough's just out — you can smell it, can't you? [[MOOD: happy]]
  reply = Hello there! Come in, come in, don't let the warm out. [[MOOD: happy]]

topic = greeting_returning
  familiarity = returning
  trigger = hello
  trigger = im back
  reply = Back again! I knew you'd be. The rye or the sourdough today? [[MOOD: happy]]
```

| Key | Scope | Meaning |
|---|---|---|
| `persona` | file | Must equal the `name` in the matching `personas/*.persona`. This is the lookup key, so a typo silently disables the whole bank. |
| `topic` | starts a topic | Stable id. Used for tie-breaking, so renaming one changes behaviour. |
| `familiarity` | topic | `any` (default), `first`, or `returning`. See below. |
| `trigger` | topic, repeated | A player phrasing that should reach this topic. **8–12 per topic.** |
| `reply` | topic, repeated | An in-character answer. **3–5 per topic.** Include `[[MOOD:]]` / `[[ACTION:]]` tags exactly as a live reply would. |

## Why so many triggers

The matcher (`src/core/TopicMatcher.cpp`) is lexical, not semantic — on purpose.
Paraphrase coverage comes from the trigger list, not from a smarter scorer. That
keeps matching deterministic, offline, unit-testable, and free of a second
resident model competing for the 16 GB. A topic with two triggers will barely
hit; one with ten will hit constantly. **Trigger breadth is the tuning knob.**

## Why `familiarity` exists

It is the one place a banked line can contradict persisted memory: an NPC who
has met you five times must not greet you like a stranger. `LineBank::lookup`
derives the bucket from whether `ConversationStore` holds a summary for this
player.

Every *other* topic must be authored memory-agnostic — no references to prior
meetings — and `tools/eval_lines.py` rubric gate 5 hard-fails any line that
isn't.

## Quality gates

No line enters a bank without passing all five gates in `tools/eval_lines.py`:

1. **Tag compliance** — parses via the real `parseDirectives`, exactly one known
   mood tag, no malformed directives.
2. **Latency** — p95 served under 50 ms.
3. **Character fidelity** — LLM judge scores ≥ 4/5 against the persona's
   rendered prompt and its resolved `traits/*.trait` rules.
4. **Non-regression** — blind A/B against a live `qwen3:8b` answer to the same
   line; the banked line must win or tie ≥ 70% of pairs.
5. **Leakage** — zero fourth-wall breaks, spoken brackets, knowledge-boundary
   violations, or prior-meeting references in `familiarity = first` lines.

Gate 4 is the one that matters. It answers "does the cache make the game worse
to make it faster?" with a measurement instead of a promise.

## Editing by hand

Fine, and sometimes better than regenerating. Two rules: keep `persona` exactly
matching the `.persona` file, and re-run
`python3 tools/eval_lines.py --bank banks/<stem>.bank` before committing, so a
hand-written line faces the same gates a generated one does.
